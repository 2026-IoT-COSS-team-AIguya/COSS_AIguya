# text_to_sign

일반인이 입력한 문장에서 뽑은 키워드(`sentence_generation/extract_keywords.py`
결과) -> 농인 사용자에게 보여줄 수어 영상.

## 왜 이런 구조인가

아바타 생성 없이, **이미 확보된 실제 수어 영상 클립**을 보여주는 방식이다.
새로 개발할 게 없어서 제일 빠르고, 무엇보다 AIHub 영상은 전문 수어사가
촬영한 정확한 수어라 신뢰할 수 있다.

**단어별로 따로따로 보여준다**(`lookup.find_all_clips()`). 수어는 어순/문법이
한국어 구어와 다른데, `extract_keywords.py`가 뽑아주는 순서는 그냥 "한글
문장에 등장한 순서"일 뿐 실제 수어 어순이 아니다. 여러 단어를 하나의 영상으로
이어 붙이면 "이게 올바른 수어 문장이다"라고 잘못 암시하게 되므로, 하나로
합치지 않고 개별 단어 카드로 따로 보여주고 순서 해석은 보는 사람에게
맡긴다(원래 DEMO_SCENARIOS.md의 "키워드 카드" 설계와 동일한 방향).

영상 출처가 세 가지라 우선순위를 둔다 (`lookup.py`):
1. `ai/data/sign_words/{단어}/{단어}_F.mp4` -- AIHub 단어 영상(정면), 전문 수어사
2. `ai/data/reference_clips/{단어}/{단어}_ref1.mp4` -- AIHub 문장영상에서 자른 것, 역시 전문 수어사
3. `ai/data/recorded/{단어}/*.mp4` -- 팀원 직접 촬영본. **AIHub에 그 단어가
   아예 없을 때만** 최후의 수단으로 사용한다 -- 팀원이 수어 전공자가 아닌 이상
   정확한 수어라고 보장할 수 없기 때문(이 영상들은 원래
   `sign_recognition` 재학습용으로 찍은 것이고, 여기선 fallback일 뿐).

## 파일 구성

| 파일 | 역할 |
|---|---|
| `lookup.py` | 단어 -> 영상 클립 경로 찾기 (우선순위 적용). `find_all_clips()`가 기본 진입점 |

## 실행 방법

```bash
conda activate coss

# 단어별 영상 경로를 따로따로 확인 (카드 형태로 보여줄 때 이걸 씀)
python ai/text_to_sign/lookup.py 은행 카드 잠깐
```
